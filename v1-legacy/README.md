> 数据结构与算法课程综合设计的提交版本。单文件 740 行，`std::vector` 承载全部数据，
> 用 `for` 循环线性查找实现所有检索。

## 运行

```bat
run.bat            :: 需要时编译，然后启动
run.bat -r         :: 强制重新编译
run.bat -b         :: 只编译不运行
```

脚本通过 `vswhere` 自动定位 Visual Studio 并调用 `vcvars64.bat`，无需手工配置环境。

首次运行后可在菜单选 `8. 导入数据`，输入 `sample_data.csv` 载入示例数据。

## ⚠ 编码说明（重要）

源文件原为 **GBK** 编码（Visual Studio 中文环境默认）。为让 GitHub 正常显示中文，
归档时转为 **UTF-8 with BOM**，换行统一 CRLF。

**编译时绝对不要加 `/utf-8`**，原因如下：

| 编译方式 | 源文件读取 | 二进制中文字面量 | 控制台代码页 | 结果 |
|---|---|---|---|---|
| 原版：GBK + 无 `/utf-8` | GBK | GBK | 936（`CP_ACP`） | ✅ 正常 |
| 归档：UTF-8 BOM + **无** `/utf-8` | UTF-8（BOM 识别） | **GBK**（自动转执行字符集） | 936 | ✅ 正常 |
| 归档：UTF-8 BOM + **加** `/utf-8` | UTF-8 | **UTF-8** | 936 | ❌ 乱码 |

MSVC 的「源字符集」与「执行字符集」是两个独立开关，`/utf-8` 会同时设置两者。
本版依赖"源 UTF-8、执行 GBK"这个组合，加上 `/utf-8` 就破坏了后者。

`run.bat` 里已按正确方式配置，直接用它编译即可。

## 已知缺陷（v2 的重构动机）

保留这份清单，是因为它们是 v2 每一项改动的出发点。

### 数据结构层面

- **所有检索都是线性扫描** `O(n)`。数据量上千后操作明显卡顿。
- **没有任何有序索引**：无法按价格/库存排序，无法查"20~50 元的商品"，无法做低库存告警。
- **日志用 `vector` 承载**：扩容时整体搬迁，且无法限制最大条数。

### 健壮性层面

- **`cin >> int` 输入非数字后菜单无限刷屏**（`failbit` 置位后每次读取立即失败，循环空转）。
- **修改商品时混用 `cin >>` 与 `getline`**，残留换行导致输入错位。
- **日志只在正常退出时保存**，异常退出（直接关窗口）则全部丢失。

### 数据安全层面

- **用 `sizeof(size_t)` 写文件**：64 位编译产物写出的文件，32 位版本读不了。
- **无任何校验**：文件被截断或损坏时，读到的是垃圾数据而非明确报错。
- **写入非原子**：写到一半崩溃，原文件已被破坏，数据全丢。

### 中文环境层面

- **源文件硬编码 GBK**，非中文系统或 UTF-8 编辑器下全乱码。
- **`setw` 按字节补齐**，中文表格必然错位。
- **相对路径读写数据**，双击运行与命令行运行的"数据"是两份。

### 性能层面

- **每次写操作都全量序列化落盘**，批量导入退化为 `O(n²)`。
- **无排序算法**，`#include <limits>` 缺失（靠间接包含编过），`SetConsoleTitle(L"...")` 在非 UNICODE 配置下直接编译失败。

逐项修复方式见 [../docs/04-engineering-notes.md](../docs/04-engineering-notes.md)
与 [../docs/05-version-comparison.md](../docs/05-version-comparison.md)。
